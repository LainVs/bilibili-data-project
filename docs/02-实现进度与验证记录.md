## 2. 已落地代码清单（实现对照方案）

项目根目录：`bilibili-data-project/`

### 2.1 配置层 `config/`

| 文件 | 职责 |
|---|---|
| `settings.ini` | MySQL 连接、Cookie、UA、请求间隔、重试、增量间隔 |
| `bili_cookie.txt` | **独立存放 Cookie 原文**（含引号不解析，gitignore 已排除） |
| `__init__.py` | 配置读取（RealConfigParser，可保留 `%` 与双引号） |

**Cookie 加载优先级**：环境变量 `BILI_COOKIE` > `config/bili_cookie.txt` > `settings.ini`。

关键设计决策：
- 使用 `configparser.RawConfigParser`（**禁用 `%` 插值**），避免 Cookie 中 `%3D`、`%2A` 等被错误替换。
- Cookie 内含双引号（如 `bmf_af_scr` 的 JSON 值），因此**外层不加引号**，避免解析报错。
- Cookie 独立成文件，避免 ini 引号/转义问题，且与代码分离便于更换。

## 4. 开发中踩过的坑（记录备查）

### 4.1 ini 配置陷阱
- **BOM 头问题**：Write 工具写出的 `settings.ini` 带 `\ufeff`，`configparser` 直接报 `MissingSectionHeaderError`。→ 改用无 BOM UTF-8 写入。
- **`%` 插值**：Cookie 含 `%3D%3D` 等，默认 `ConfigParser` 会做插值导致崩溃 → 换 `RawConfigParser`。
- **Cookie 含双引号**：`bmg_af_scr={...}` 带引号，外层再包引号会被截断 → Cookie 移入独立文件。
- **注释误读**：cookie 文件中的注释行会被当 Cookie 读入 → 加载器过滤 `#` 开头行。

### 坑2 Cookie 泄露风险
- 首次尝试直接把 Cookie 塞进 ini 时，误写了一串非原样的伪造值 → 立即纠正：**真实 Cookie 由用户粘贴到 `bili_cookie.txt`**，代码绝不改写。
- `.gitignore` 已排除两个敏感文件。

### 坑3 protobuf 手写解析
- 弹幕接口返回 protobuf（非 XML），手写极简解析器需**容错**：未知字段号跳过、越界保护、解码失败降级空列表，避免整个任务崩溃。

### 坑4 跨模块引用不一致
- 早期 `full.py`/`resolve_uid.py` 引用不存在的 `update_last_error`、损坏的 `_load_meta` → 统一收敛到 `dao` 层方法并重写。

### 弹幕采集链路（本会话核心攻克）

**接口实测结论：**

| 接口 | 路径 | 结果 |
|---|---|---|
| 历史弹幕数据 | `GET /x/v2/dm/web/history/seg.so` | ✅ `code=200`，返回 protobuf 二进制 |
| 弹幕日期索引（**已失效**） | `GET /x/v2/dm/history/index` | ❌ `-400` 任何参数形式（含月/日格式、http/https、wbi 签名）均失败 |
| 弹幕日期索引（旧路径） | `/x/v2/dm/list/index` | ❌ 404（路径不存在） |

**关键踩坑与修复：**

1. **`seg.so` 用 JSON 请求会失败**：弹幕接口返回的是 protobuf 二进制，`get_json` 无法解析。→ `client.py` 的 `get_bytes` 增加 `params` 支持，弹幕走 `get_bytes`。
2. **`parse_dms` 函数名错误**：代码调用 `_parse_one` 但定义是 `_parse_dm` → 修正函数名。
3. **翻页死循环（重要）**：实测发现 `seg.so` **忽略 `segment_index`**，任一索引都返回当天全部弹幕（如 2020-01-21 返回 1492 条/125KB）。原 `_fetch_day_all` 会因 `len>500` 无限翻页 → 改为**每天只请求一次**。
4. **日期索引接口失效** → 放弃依赖，改为"**采样探测 + 逐日全量**"：
   - B站每天弹幕至多约 500 条，超出顺延到后续日期返回，**必须逐日请求才能保证完整**。
   - 先"近期 7 天逐日 + 指数回溯 + pubdate 首日"抽样判断该视频是否有弹幕；无弹幕视频（如 BV1bW411n7fn）几十次请求内即可判空跳过，解决老视频全量空转痛点。
5. **protobuf 解析验证通过**：对 2020-01-21 真实数据解析出 **1492 条弹幕**，`mid_hash` 100% 存在，字段（id/progress/mode/color/ctime/mid_hash/content）均正确。
