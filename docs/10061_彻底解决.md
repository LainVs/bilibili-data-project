# 10061 彻底根因分析与解决（双库 D3306/E3307）

## 现象
`13:06:35-57` 连续 `2003 (10061) 由于目标计算机积极拒绝，无法连接`，`D→E` 归档全失败，`E` `3307` 无 `LISTENING`，手动点 `管理员重连E` 仍 `10061`。

## 直接原因
`MySQL80-E` 没 `Running`，`3307` 未 `LISTENING`，`SYN_SENT` 就 `10061`。

## 深层链条（按时间序）

1. **热插拔脏文件系统**  
   `E` 是 `HDD`，拔盘未 `安全弹出` → `NTFS` 脏标记 → `ibdata1` 被 `mysqld` 句柄锁死，`Can't create test file` / `must be writable`。

2. **双服务端口抢占**  
   `my.ini(E,3306)` 残留进程占 `3306`，`my_D.ini(3306)` 与 `my_E.ini(3307)` 同起时 `Bind on TCP/IP port: ... only one usage`，`MySQL80(D)` 起不来。

3. **大缓冲+二进制日志崩溃**  
   `my_E.ini 2G` + `log-bin` + `Zstd` 在 `HDD` 上 `14M` 恢复时 `do_reset@Zstd_dec` 崩，`LAPTOP-E-bin.000007 not found` → `Can't init tc log`，服务 `StartPending→Stopped`。

4. **HDD 上 FULLTEXT 锁**  
   `raw_comments.FULLTEXT(content)` `13M` 倒排 `1.5G`，`HDD 100 IOPS` 上每 `INSERT 1行` 要更新倒排 `12秒`，`500/批` 必 `1205 Lock wait` / `2013` 超时，`archive_sync` 的 `COMMIT waiting 433秒` 卡死。

5. **UI 误判**  
   `connection_panel` 自动 `net start` 无管理员 `5 拒绝访问`，二次点击撞 `START_PENDING` 闪退。

## 已落地的彻底修复

* **双库分离**：`D(3306,SSD/稳定盘)` 采集直写，`E(3307,HDD)` 归档查询，`storage/db.py:14` `get_conn(role)`，`dao.py` 读写分离（`_w=D`/`_r=E` 回退）。
* **归档幂等**：`archive_sync.py:51` `D与E同库保护`，`64` `ON DUPLICATE KEY UPDATE` 不丢更新，`D` 成功才 `DELETE`。
* **HDD 适配**：`my_E.ini` `128M`（`1G` 在 `HDD` 上 `Zstd` 崩，已回退）、`skip-log-bin` 已加、`innodb_flush_log_at_trx_commit=2`+`sync_binlog=1000`（每秒刷盘，`COMMIT` 不卡 `53秒`）。
* **FULLTEXT 已删**：`E` 上 `DROP INDEX ft_content`，`500/批` → `100/批`，单行 `12秒→0.08秒`，`100行 0.17秒`，`1000行 2秒`。
* **UI 不冻**：`collect/broad/search` 全改后台线程，`connection_panel` 加 `管理员重连E`（`runas`）+ `手动归档` 进度条/日志 + `清理卡死`（`KILL >60秒`）。
* **统计不0**：`dao.py:541` `COUNT(*)→information_schema.table_rows` `0.4秒`，`stats_cache` 双写本地 `storage/stats_cache.json`，`E` 离线回退文件。
* **配置原子**：`config/__init__.py:133` `mkstemp+os.replace+fsync` 防 `0字节`，空 `port` 回退默认值。

## 手动一键恢复（热插拔后）
1. 插回 `E` 盘，等 `E:\MySQLData\data` 可见
2. 管理员 `PowerShell`：`chkdsk E: /f`（若提示脏）
3. `连` 面板点 `管理员重连E`，等 `服务:Running` + `netstat -ano | findstr 3307` 有 `LISTENING`
4. 点 `手动归档 D→E`，看进度条走完
5. `统计` 点 `刷新` 一次落 `E` 缓存

## 预防
* 拔 `E` 前 `连` 面板 `检测` 确认 `E` 无 `COMMIT waiting`，或先 `net stop MySQL80-E`
* 保持 `my_E.ini 128M` + `skip-log-bin`，别回 `2G`/`log-bin`
* `E` 用 `SSD` 可彻底告别 `60秒` 冷启和 `FULLTEXT` 慢（可选）
