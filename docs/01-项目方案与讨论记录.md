# B站弹幕/评论采集与存储项目 — 方案与讨论记录

> 状态：方案已定型，进入实现阶段
> 日期：2026-08-08

---

## 1. 项目目标

采集 **B站视频的弹幕与评论**，以及与之相关联的 **用户 UID**，并将数据持久化到 MySQL 数据库。

本项目为 **学习 / 练习性质**，重点在于跑通「采集 → 清洗 → 存储 → 分析」全流程，并理解其中的技术原理（含反爬与反查算法）。

### 3.2 关键可行性结论

1. **评论 + UID：完全可行（直接获取）**
   `/x/v2/reply/main` 返回每条评论带 `mid`（UID）与 `member`（昵称/等级/性别/大会员/IP属地）。

2. **弹幕 + UID：可行但需反查（本项目核心难点）**
   现弹幕接口 `seg.so` 只返回 **`mid_hash`**（发送者 UID 的哈希），不直接给 UID。
   通过 CRC32 破解可反查出真实 UID，代价是额外计算开销与一定失败率。

3. **反爬现状（2025-2026）**
   - 评论接口已上 **`w_rid`（MD5 签名）+ `wts`（时间戳）**，必须模拟签名。
   - 评论接口 **需要已登录 Cookie**。
   - 弹幕历史接口有 **每段 500 条** 限制，拿"完整"需分段多次请求。
   - 国内单账号低并发 + 限速即可，**无需代理池**（中规模内）。

### 3.3 mid_hash 反查原理与风险

**mid_hash = UID 的 CRC32 值**（ITU I.363.5 标准，多项式 `0xEDB88320`），非不可逆加密，可暴力破解反查。

| 风险 | 说明 | 应对 |
|---|---|---|
| 10 位以上 UID 会失败/查错 | CRC32 破解对 8~9 位 UID 有效 | 反查失败降级存 mid_hash，标记未解析 |
| CRC32 碰撞 | 极小概率两 UID 同 hash，结果不准 | 二次校验（比对弹幕内容/用户信息） |
| 性能 | 逐个破解耗时 | 预计算 CRC 彩虹表 + 结果缓存（同 mid_hash 只查一次） |

## 4. 技术架构

### 4.1 整体流程图

```
┌────────────────── 采集层 ──────────────────────────────┐
│  config: 手动BV列表(可扩展) ──► 全量采集 ──► 增量采集(定时) │
│  请求封装: 登录Cookie / 随机UA / 限速(0.5~1s) /            │
│  重试退避 / 断点续传 / 日志                                │
│      ▼                                                   │
│  B站接口: 弹幕API(拿mid_hash) + 评论API(直接拿mid)         │
└──────────────────────┬────────────────────────────────────┘
                       ▼
┌────────────────── 清洗 / 规范层 ───────────────────────┐
│  字段抽取 │ 类型转换 │ 去重 │ 完整性校验(数量对数)        │
│  mid_hash → CRC32 反查 → 真实UID（彩虹表+缓存）           │
└──────────────────────┬────────────────────────────────────┘
                       ▼
┌────────────────── 存储层 (MySQL) ──────────────────────┐
│  raw_danmaku   (弹幕 + uid/mid_hash + video_id)         │
│  raw_comments  (评论 + uid + video_id + 楼层)            │
│  dim_user      (UID 维度, 去重汇总)                      │
│  meta_video    (BV/cid 映射, 后续扩展)                   │
│  增量: INSERT ... ON DUPLICATE KEY UPDATE (幂等)         │
└──────────────────────┬────────────────────────────────────┘
                       ▼
┌────────────────── 分析 / 可视化层（可选阶段） ───────────┐
│  SQL 取数 → Matplotlib/Plotly 图表:                     │
│  热门弹幕/高频UID/评论热度/时段趋势                      │
└─────────────────────────────────────────────────────────┘
```

## 5. 核心保障设计

- **断点续爬**：采集进度落盘（完成的 video_id / 分页游标），中断后恢复。
- **限速重试**：429 / 网络错误 → 指数退避重试；接口限制时降速不放弃，跳过项记日志。
- **完整校验**：每视频校验 弹幕数 + 评论数 vs 接口返回总数，缺口告警并补采。
- **幂等写入**：唯一索引（弹幕 dmid / 评论 rpid），重复采集不产生脏数据。
- **弹幕 UID 降级**：反查失败存 mid_hash，标记 `uid_resolved=0`。
